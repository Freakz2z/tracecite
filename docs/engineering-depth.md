# TraceCite 独立工程职责与案例

更新日期：2026-10-18（北京时间）。正式版本为 0.8.0；本文新增差异引擎和本地一致性保护处于 0.9.0 开发线，尚未正式发布。

## 对组委会意见的回应

原申报简介突出引文匹配、调用与来源关联，未充分解释来源验证中的工程职责。TraceCite 当前承担四项可分别验证的工作：独立读取来源并执行访问边界；解析并限定引用的实际依赖范围；计算来源版本之间的多处行差异；控制检查、只读候选和基线写入的状态转换。

开发线进一步新增 MoonBit 行差异引擎和本地输入/基线版本检查。差异引擎采用标准 LCS 方法，独立实现有资源上限的计算、确定性回溯、观察坐标和诊断接入，提供跨 native、JS、Wasm 的公共 API；native CLI 则在提交前重新验证本地输入和目标基线。标准算法本身不作为原创研究成果；本项目的工程贡献由源码、边界行为和端到端案例检验。

可用于补充申报的说明：TraceCite 的实质职责包括确定引用依赖的来源范围、独立回源并执行访问策略、在资源预算内计算来源版本的多处差异，以及根据输入版本和验证状态控制基线提交。章节链接仍有效且没有引文可匹配时，工具仍能发现章节中相隔 120 行的配置变化；扫描成功后来源再次改写或另一写入者更新基线时，工具会拒绝保存过期结果。这些行为由 MoonBit 实现，并附可执行正反案例、原始报告及摘要。当前证据属于受控回归和固定真实历史回放，尚不等于外部采用或验收通过。

## 案例一：章节存在，但两项配置同时变化

受控项目只有一条章节链接，没有待匹配的引文。链接指向运行配置章节，章节中超时由 20 改为 30，权限由 read 改为 write，两项相隔 120 行稳定内容。

两个版本都检测到来源变化并返回退出码 2，完整基线候选一致。正式 0.8.0 的原有展示片段没有包含第二处权限修改；0.9.0 的行差异结果包含两个编辑块，在观察文本第 2 和 123 行分别列出新旧值。审阅者因此能直接看到两项修改。

先修改同一文件的另一个章节时，检查保持通过，说明被比较的是引用所依赖的选中范围。演示还断言完整候选保留所有稳定行，差异展示不会裁掉快照证据。

这里的行号从已保存/当前观察文本的第一行开始，属于观察坐标。它们可能来自完整章节、指定行范围或引文附近上下文，不能直接当作源文件的绝对行号。

## 案例二：大面积改写与受限计算

将同一章节的 520 行替换为另一组 520 行，剥离共同标题后，LCS 表仍超过单次调用预算。结果为 complete=false、reason=cell_limit；增删数量和总编辑块数量缺省，表示尚未算出这些值。

来源变化诊断仍退出 2。显式同时指定旧基线和快照目标的写入被拒绝，旧文件字节保持一致。另一个绑定配置片段被实际来源否定的案例中，只读预览不给出可写快照；尝试保存也不覆盖旧基线。这些状态断言见 [可执行案例](../scripts/engineering_demo.py)。

单次差异调用的边界如下：

| 项目 | 上限与含义 |
| --- | --- |
| 输入 | 每侧 262144 个 UTF-16 单元，超限为 input_limit |
| 行数 | 每侧 16384 行，超限为 line_limit |
| LCS 表 | 剥离相同首尾后，包含边界行/列共 262144 个单元，超限为 cell_limit |
| 展示 | 最多 20 个编辑块，每侧最多 512 个 Unicode 字符及省略标记 |

complete 表示计算是否完成，display_truncated 表示展示是否省略，两者独立。完成计算后，即使只展示前 20 个编辑块，总编辑块数与增删行数仍是完整统计。预算约束针对单次调用；整个报告的开销还与引用数量有关。

## 案例三：来源不可越过读取边界

同一演示请求引用工作区外一个确实存在的文件，得到 SOURCE_OUTSIDE_ROOT；将来源改为本机 HTTP 地址，得到 INVALID_OR_BLOCKED_URL。两者均退出 2。案例记录诊断代码，不把读取失败说成引文不匹配。

现有单元测试还覆盖重定向目标、地址解析、代理选择、HTML 文本提取与字符集。本轮未新增完整网络隔离系统；DNS 检查与实际连接的地址绑定、可重放响应证据仍列入下一阶段，不据现有地址筛查声称已经消除全部 DNS 重绑定风险。

## 案例四：已有真实历史回放

[固定上游提交的历史回执](field-validation/maintenance-history.json)保存 moonbitlang/moon 两份真实文档的一次来源变更：章节链接仍有效，但选中章节发生更新，基线要求复核；明确复核并保存后再次通过。具体版本、命令和限定范围见 [维护试用说明](maintenance-trials.md)。

差异引擎阶段用 0.9.0 与正式 0.8.0 重跑相同固定提交，[阶段回执](cases/engineering-history-0.9.0-development.json)保留两处诊断及各自的结构化行差异。检测、覆盖与完整候选一致，原有展示字符数也相同；没有将它记为新的展示量或工时收益。

该案例是历史回放，本轮前三类是受控回归；外部维护者采用、自然问题发生率和节约工时仍待实际使用证据支持。

## 案例五：扫描通过，但提交时输入已过期

配置片段与来源的 timeout=20 完全匹配，扫描报告无失败。演示在真实 CLI 输出扫描报告、尚未提交时，分别修改来源文件、文档、项目配置或目标基线。前三种得到 CHECK_INPUT_CHANGED，最后一种得到 SNAPSHOT_CONFLICT；四次都退出 2，原有基线或另一写入者的内容保持不变。[四步回执](cases/consistency-0.9.0-development.json)保存退出码、提交诊断和前后摘要；[驱动脚本](../scripts/consistency_demo.py)还保存每一步原始 JSON 和 stderr。

实现先记录已读取文件的完整字节、文件类型与解析后的路径，在报告前复查；写入时独占创建目标旁的临时文件，再次验证输入和扫描前的目标字节，最后重命名。另一 TraceCite 写入者占用临时文件时直接停止；若它已提交，旧目标字节比较会拒绝过期写入。正常内容未变时可以提交，刷新观察后可以重试；失败只清理本进程的预约。额外 native 回归验证同长度改写、删除、符号链接改向，以及先普通链接再绑定片段时仍记录内容依赖。

演示用容量明确为 4096 字节的 Linux stdout 管道建立屏障，不用延时猜测或产品内测试开关。它也验证消费边界：JSON 代表扫描阶段，报告无失败仍可能在提交阶段退出 2，调用方必须读取进程退出码和 stderr。管道案例限 Linux；七项 MoonBit 状态测试不依赖该屏障。

保护范围是本次运行观察到的本地输入；普通链接只验证存在性和目标，实际读取的章节/片段来源则复查全文字节。当前实现不锁住外部来源，不能消除最终复查后的外部写入窗口，不检测改后又恢复相同字节的历史，也不保证多文件事务。HTTP 版本和两次命令之间人工预览候选的身份绑定仍未完成，不能据此声称任意复核后的变化都已被阻止。

## 复现与校验方法

执行步骤见 [工程职责演示](../examples/engineering/README.md)。[差异引擎阶段回执](cases/engineering-0.9.0-development.json)记录真实 CLI 退出码、两个差异块、预算回退、与 0.8.0 的对比，以及该阶段的二进制和实现文件摘要；原始 JSON 报告由演示保存在输出目录。一致性增强另有上述四步回执，保留旧阶段证据，不将旧摘要替换成后续源码摘要。

算法测试对 a/b 两种重复行、长度 0 至 4 的 31 个序列做两两穷举，共 961 对。独立判据枚举子序列，验证增删数量最小；再按差异块回放，验证能逐字重建目标文本。另有空文件、末尾换行、CRLF、Unicode、预算边界、大量相同首尾、重复行回溯和展示截断回归。

该说明提供可转交的实现和案例依据。后续工作按 [Roadmap](../ROADMAP.md)补齐连接级回源边界、可重放来源版本证据、跨运行候选绑定与真实持续维护案例，完成情况逐项记录。

本轮验证为 native 141 项、JS/Wasm 各 119 项、CLI 80 项、报告契约 9 项；包含七项 native 一致性状态测试及四个扫描后真实 CLI 冲突案例。此前差异引擎一轮已完成源码 ZIP 解包安装、每目标 11 项公共 API 消费及独立库样例，Linux 独立包候选跑通工程演示，14 份实际报告按 JSON Schema 2020-12 校验通过。正式 0.9.0 注册表与跨平台交付仍未执行。

工具链说明：本轮主线兼容升级到 moonc v0.10.15+943464bfa、moon 0.1.20261012（748b63c），采用新规范的 Int32 类型名和可选标签参数写法；0.10.14 无法编译这些新类型名。CI 安装官方 latest 后先核对已验证的编译器和构建工具身份，版本漂移时先停止再单独复核。历史 SDK 固定地址未能取得，本项目不声称其下载来源已被永久锁定。正式 0.8.0 的源码和发布身份保持原样。
