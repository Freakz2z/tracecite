# TraceCite 项目申请表

1. **项目名称**：TraceCite——AI Agent 引用回源验证与来源变化检测工具。

2. **项目简介**：Agent 给出的链接和引文可能看似可信，却已被误抄、删除或修改。TraceCite 用 MoonBit 独立读取网页或本地文件，核对引用片段是否出现在当前来源中，并比较两次运行的来源变化，帮助开发者在交付回答前发现需要复核的证据。

3. **项目方向与通用性**：AI Agent 开发者工具、可信输出。只需 `claim + quote + URL` 三行即可验证网页引用，无需接入特定模型或适配器；需要审计工具调用时，也支持公开 JSONL 约定。Codex CLI 适配器仅是一个接入示例，其他 Agent 和 RAG 系统可生成同样的输入。

4. **预期使用场景**：
   - **RAG 报告发布前**：编辑者从报告中整理主张、逐字引文和网页 URL，运行回源校验；若引文不在当前网页中，CI 返回失败，编辑者更换证据或修订报告后再发布。
   - **本地资料引用复核**：文档分析 Agent 引用仓库文件并导出 JSONL 轨迹；审核者运行文件回读校验，找出轨迹记录与当前文件不一致的引用，避免把过期或篡改后的资料当作有效证据。
   - **Agent 更新后的回归检查**：团队在模型、提示词或知识库更新前后各保存一次运行轨迹；TraceCite 按来源 URI 报告新增、删除及内容变化，让团队定位需要重新审阅的回答。

5. **核心功能**：已实现三行引用笔记解析、HTTP/HTTPS 网页回源与 HTML 可见文本提取、引文片段匹配、本地文件回读、JSONL 调用与引用关联校验、跨运行来源比较，以及适合 CI 使用的退出码和 JSON 报告。仓库提供 IANA 网页回源样例（引文 1/1 匹配）和两次真实 Codex CLI 运行的脱敏轨迹（检测到 1 个来源变化）。

6. **项目性质**：原创项目，非移植项目。输入约定、验证流程、命令行工具和核心校验逻辑由本项目设计实现。

7. **移植来源及许可证**：不适用。项目采用 OSI 认可的 Apache-2.0 许可证；使用的 `bobzhang/html_parser` 依赖同样采用 Apache-2.0 许可证。

8. **GitHub 仓库**：[Freakz2z/tracecite](https://github.com/Freakz2z/tracecite)。公开主分支已有超过 10 条有效开发提交，README 提供安装和复现命令，CI 覆盖检查、构建、测试与示例；[0.1.0 已发布到 Mooncakes](https://mooncakes.io/docs/Freakz2z/tracecite)。

**验证边界**：工具确认引文在检查时出现在独立读取的来源中；它不判断整条主张的语义真假，也不证明网页在 Agent 原始运行时的内容。
