# TraceCite 项目重新申报书

1. **项目名称**：TraceCite——Agent 回答的引用证据校验与跨运行变化检测。
2. **项目简介**：用 MoonBit 核对 Agent 回答引用的逐字片段与工具返回内容；对本地文件可重新读取原文件，识别被篡改的输出；还能比较两次运行的来源变化。输出含行号、错误码与 JSON 报告，适合本地检查和 CI 门禁。
3. **项目方向与通用性**：面向 Agent 可信执行与评测。核心库不绑定某个模型或平台，采用公开的 JSONL 事件约定；现有 Codex CLI 适配器可把真实命令事件导入，其他 Agent 可按约定导出。跨运行比较使用稳定来源 URI，适用于文件读取、搜索和 RAG 检索结果。
4. **预期使用场景**：
   - 开发者在 RAG 应用发布前导出一次问答轨迹；若回答引用了来源中不存在的逐字片段，校验器报 `QUOTE_NOT_IN_SOURCE`，CI 阻止发布该结果。
   - Agent 执行命令读取本地资料并给出带引用的答复；适配器保留工具输出，校验器再独立读取文件核对完整内容，篡改输出、未知来源或失败调用都会被标记。
   - 维护者在知识库更新前后分别导出运行轨迹；比较器按来源 URI 报告新增、删除和内容变化，便于定位哪些 Agent 答复需要重新审核。
5. **拟实现的核心功能**：轨迹结构与调用链校验；逐字证据匹配；本地文件独立复核；未引用主张检测；跨运行来源内容比较；稳定诊断、命令行和 JSON 输出；native、JS、Wasm 目标测试。
6. **项目性质**：原创项目，非移植项目。JSONL 格式和校验逻辑由本项目设计实现。
7. **移植来源与许可证**：不适用；项目本身采用 Apache-2.0 许可证。
8. **GitHub 仓库**：[Freakz2z/tracecite](https://github.com/Freakz2z/tracecite)。仓库具有不少于 10 次实际开发提交，无空提交或重复提交凑数。

**能力边界**：逐字匹配证明片段出现在采集的工具输出中；文件复核证明输出与校验时的本地文件一致。尚不验证网页真实性、历史文件状态或整条主张的语义正确性。跨运行比较依赖稳定 URI。
